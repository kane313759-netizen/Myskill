# Escalate to Sol

Use a Sol 6.1 analysis worker when architecture is ambiguous, constraints conflict, a bug survives two focused fixes, multiple modules are implicated, or a mandatory tool/optimization decision materially changes the design.

Read EXAM_POLICY.md and the canonical `hackathon-orchestrator` protocol. Start without inherited dialogue (`fork_turns="none"` where supported, otherwise a clean session); pass original source paths, relevant current files/tests, the exact failure, and labeled hypotheses. Ask for evidence and a minimal plan first. MAIN remains the sole product-source writer; this worker returns analysis only and does not write shared notes or STATE/gate records.

Preserve the official scoring objective and exam restrictions: no invented penalties/limits, wholesale external implementation, Computer Use/automated UI control, external AI connection, external task-data transmission, or Git Push. Report material spec changes to ORCHESTRATOR for gate reopening and targeted clean review; this analysis does not replace CP1/CP3 approval.
