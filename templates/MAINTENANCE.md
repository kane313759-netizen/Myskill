# 유지보수 안내

실제 코드·설정 이름과 검증 결과를 채운다. 설정을 바꿨는데 결과가 같다는 이유만으로 오류 또는 최적이라고 단정하지 않는다. 목적함수·제약·독립 재계산·작은 정답 사례와 비교해 설명한다. P2 change_test/tune 없이도 P1 운영이 가능하다.

| 변경 | 고칠 실제 위치 | 재실행·예상 관계 | 독립 검증·한계 |
|---|---|---|---|
| 용량·단가·임계값 변경 | 미확인 | 새 설정으로 결정 모듈 재계산 | 미검증 |
| 입력 형식 변경 | 미확인 | 파서·스키마 검증 | 미검증 |
| 결측·오류 입력 | 미확인 | 검증된 보수 판정/이관과 경고 | 미검증 |
| 업무 규칙 추가 | 미확인 | 제약·목적함수·회귀 재검토 | 미검증 |

가능해·실행 가능한 해·관측 후보 중 최선·전역 최적을 구분한다. 전역 최적은 해당 알고리즘의 보장과 적용 전제 또는 독립 오라클이 있을 때만 쓴다. 후보 출력으로 정답을 만들지 않는다.

## r2 최소 실제 변경 실행 2건

서로 다른 변경 두 건을 각각 격리된 사본에서 실제 실행한다. 변경 전후 설정·실행 프로그램·실제 명령과 stdout·검증 결과를 해시 참조로 `records.maintenance.runs`에 연결한다. 미실행, 동일 설정, 계획만 있는 기록은 통과가 아니다. 각 변경의 예상 관계와 비교 기준이 맞는지는 별도 검토한다.
