# 데이터 감사 기록

`data_audit.py` 출력 JSON을 이 문서의 유일한 JSON 블록으로 보존하거나 별도 JSON 기록을 참조한다. 제공된 파일만 검사한다. 경로·SHA256·검사 행 수·최대 바이트·샘플 한계를 남긴다. 출처 범주 값은 결과에 포함될 수 있으므로 민감도를 검토한다. `RECORDED`는 관찰 기록이며 업무적으로 안전하다는 인증이 아니다. 자동 확인이 불가능한 항목은 `UNVERIFIED`로 유지하고 독립 DATA_EVAL_RED가 실제 증거를 검토한다.

| ID | 검사 | 확인 방법·발견·조치 또는 N/A 전제 |
|---|---|---|
| 1 | 시각 역행·지연·시간대 | 미검증. 시간처럼 보이는 컬럼이 있으면 N/A 불가 |
| 2 | 단위·스케일 변화 | 미검증 |
| 3 | 코드·정의 개정 | 미검증 |
| 4 | ID·조인 행 폭증 | 미검증 |
| 5 | 결과 누수 | 미검증 |
| 6 | 표본 편향 | 미검증 |
| 7 | 교란 변수 | 미검증 |
| 8 | 분포 이동 | 미검증 |
| 9 | 폐기 문서·위험 지시문 | 미검증 |
| 10 | 결측·이상값의 원인 | 미검증 |

표 데이터가 없는 문서 과제는 해당 전제가 확인된 항목만 N/A 가능하다. 빈 파일·일부 표본·읽기 실패를 전체 데이터 확인으로 바꾸지 않는다. 이 기록의 경로와 현재 SHA256을 SPEC_DRAFT 검증 계획에 함께 적어 CP1 독립 리뷰에 포함한다. N/A 목록은 학습 시간에 보여 주며 참가자 확인을 작업 선행 조건으로 삼지 않는다.

## r2 시험 보완

명시 입력 전체를 안전 예산 안에서 검사하고 gzip CSV·인접 구간 스케일 변화·같은 행의 시작/종료 역행 후보를 기록한다. 읽기 바이트·시간·줄 길이 상한에 도달하면 범위 미완료를 기록하고 최종 검사를 통과시키지 않는다. 데이터 순서가 시간순인지, 같은 개체의 공정 순서가 맞는지, 단위가 바뀐 것인지 검증자에게 남긴다. gzip 해제 크기도 별도 제한한다.

명시된 역할 또는 일반 명칭 힌트를 사용해 같은 개체의 단계 종료와 다음 단계 시작을 비교한다. 개체·출처 통계는 bounded reservoir 표본이며, 제안 시차는 자동 적용하지 않는다. 중복 단계·재작업·분기·시간대 의미는 확정하지 않는다.

## r3.1: 스캔과 분석 범위 구분

UNVERIFIED는 행을 다 읽지 못한 경우만, 분석 축소는 경고로 기록한다. 파일별 analysis_limits의 검사·이유·열·생략 수를 확인한다. 50개 초과 범주는 출처 그룹에서 제외하고, 출처 기준은 자기 자신을 제외한 중앙값이다. 출처별 기간 변화와 시간대 혼재를 검토한다. 시간이 없거나 시간순이 불확실하면 인접 비교를 하지 않으며 긴 형식은 범주별로 비교한다. 자동 ID 후보의 중복률과 추정 실패 시 NOT_RUN을 확인한다.
