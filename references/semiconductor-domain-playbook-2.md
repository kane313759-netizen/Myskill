# 반도체 도메인 일반 플레이북 2부 — 분석 기법·운영 기초 (`references/semiconductor-domain-playbook-2.md`)

> **최우선 적용 원칙 (1부와 동일)**
> 1. 가설을 세우고 점검하는 데 쓰는 **일반 참고서**다. 본선 지문·제공 데이터·채점기 수식·현장 답변과 다르면 **무조건 본선 쪽을 따른다.** 여기 공식·수치를 문제 정의보다 우선해 하드코딩하지 않는다.
> 2. 수치는 감각용이다. 업계 관행 기준(AIAG 등)은 회사·고객마다 다르다. 실제 판단은 과제 데이터로 다시 확인한다.
> 3. "비개발자용 설명"은 **실제로 그렇게 처리한 경우에만** 쓰는 문장 틀이다.
> 4. 주제 번호는 1부(주제 1~10)에 이어 11~16이다.
> 5. 주제별 절(3장)은 연습 과제 영역을 기준으로 고른 목록이다. 결선 과제 주제와 다르면 1장 수식·2장 공통 점검만 참고하고, 주제별 점검표로 데이터에 없는 현상을 찾지 않는다.

## 2. 데이터 공통 점검 (1부 2장에 추가)

- 분할: 같은 lot의 웨이퍼, 같은 장비의 연속 구간은 서로 닮았다. 학습·평가는 lot·기간 단위로 나눈다.
- 불균형: 정상이 대부분이면 정확도는 의미가 없다. 클래스별 재현율·macro F1, 또는 비용 가중 지표로 본다.
- 행 순서: 부분군이 없을 때 $\sigma_{within}$은 이동범위로 추정되어 **행 순서에 따라 Cpk가 바뀐다.** 정렬된 데이터는 Cpk를 부풀린다. 시간순인지 확인한다.
- 검열: 관찰 종료·예방 교체로 아직 고장 나지 않은 개체를 버리거나 고장으로 치지 않는다.
- 지표 정의: 가용률·OEE·이용률·X-factor는 회사마다 분모가 다르다. 비교 전 정의를 맞춘다.
- 집계 창: 리틀의 법칙·이용률은 장기 평균이다. 램프업·장애 직후 같은 짧은 비정상 구간으로 계산하지 않는다.

## 3. 주제별 메커니즘과 점검표

### 주제 11. 웨이퍼 맵 패턴과 의심 공정
- **메커니즘**: 불량 칩이 흩어져 있으면 공정 잡음, 모양(중심·도넛·가장자리 링·가장자리 국부·국부·스크래치·전면)을 이루면 원인이 있는 계통 불량이다. 모양은 원인 후보를 좁힐 뿐 증명이 아니다. 한 웨이퍼에 여러 패턴이 겹치기도 한다.
- **원인 후보 (가설, 장비 이력으로 확인 필요)**

  | 패턴 | 문헌에 나오는 후보 |
  | :--- | :--- |
  | 중심 원형 | 화학 얼룩, 연마 불균일·액 압력 이상, 기계 결함 |
  | 도넛·링 | 툴링(장비·치구) 문제, 세정 노즐 위치와 겹치는 링 등 (후보를 하나로 닫지 않음) |
  | 중심에서 방사형 | 회전 도포(스핀) 장비 |
  | 한쪽으로 쏠림 | 식각 가스 유입·배기 방향 같은 장비 비대칭 |
  | 가장자리 링·구역 | 열처리 온도 제어 이상, 연마 불균일, 가장자리 다이 효과 (1부 주제 2 에지 링 마모와도 대조) |
  | 샷(레티클) 단위 반복 | 노광 마스크·샷 관련 (패턴 이름 수준, 원인 근거 약함) |
  | 선형 스크래치 | 웨이퍼 취급·연마 중 이물 (관행 지식) |
- **점검**
  1. 좌표계(노치 방향·원점·뒤집힘)를 먼저 통일한다.
  2. 공간 특징을 만든다: 반경 구간별·각도 구간별 불량률, 샷 안 위치별 불량률, 이웃 칩 불량 비율.
  3. 같은 수의 불량을 무작위로 뿌린 맵과 비교해(순열) 군집이 우연인지 확인한다.
  4. 같은 패턴을 보인 웨이퍼들의 공정 이력(장비·챔버·시점) 공통점을 찾고, 장비 이력·공정 데이터·전기 테스트로 확인하기 전에는 원인이라 쓰지 않는다.
  5. 분류 모델을 만들 때: 공개 데이터 WM-811K는 라벨의 약 85%가 정상이고 전면 불량은 극소수다. 클래스별 재현율로 평가하고 lot 단위로 분할한다. 비슷한 맵에 다른 라벨이 붙는 모호성이 있다.
  6. 다이 크기가 달라 맵 크기가 다르면, 크기 조정은 최근접 보간으로 한다(합·불 같은 이산 값 보존).

### 주제 12. SPC·FDC 기초
- **메커니즘**: 관리 한계는 공정 데이터로 계산한 "평소 변동"의 경계이고, 규격 한계는 설계·고객 요구다. 관리 한계 이탈은 공정이 변했다는 신호, 규격 이탈은 불량이다. 둘을 섞지 않는다.
- **WE 규칙**: ① 1점이 ±3σ 밖 ② 연속 3점 중 2점이 같은 쪽 2σ 밖 ③ 연속 5점 중 4점이 같은 쪽 1σ 밖 ④ 연속 8점이 중심선 같은 쪽. 같은 쪽 연속 기준은 WE 8점, Nelson 9점, 일부 교재·매뉴얼 7점으로 다르니 과제 정의를 따른다.
- **자기상관**: 측정이 촘촘하면 앞 값과 닮는다. 두 경우를 구분한다. ① 한계를 실제 전체 σ로 잡으면 규칙1만의 오경보는 거의 그대로지만 런 규칙(2/3, 4/5, 8연속)이 거짓 신호를 쏟아낸다. ② σ를 이동범위로 추정하면 이웃 차이가 작아 σ가 과소 추정되고 한계가 좁아져 규칙1도 오경보가 는다. 대응: 시계열 모델을 맞춘 뒤 잔차에 관리도를 쓰거나 EWMA를 쓴다.
- **다변량**: $T^2$와 SPE를 함께 본다. 기여도 그림으로 변수 후보를 찾되, 원인 변수의 영향이 상관된 정상 변수로 **번지는(smearing)** 현상이 있어 1위 변수가 원인이라는 보장은 없다. 후보 변수는 단변량으로 다시 확인한다.
- **점검**
  1. 관리 한계는 이상이 없는 안정 구간으로 계산한다. 이상 구간이 섞이면 한계가 넓어져 둔해진다.
  2. 시차 1 자기상관을 먼저 계산한다.
  3. 켜는 규칙 수 = 오경보 예산이다. 실제 고장 유형(급변·완만한 이동·추세)에 맞는 규칙만 고른다.
  4. Cpk는 시간순 정렬과 부분군 정의를 확인한 뒤 계산하고 Ppk와 함께 보고한다.
  5. 정비·시즈닝 직후 구간은 따로 기준을 둔다. FDC 요약은 레시피 단계별로 자른다(1부 주제 3).

### 주제 13. 팹 운영 공식
- **메커니즘**: 대기 시간은 이용률에 비선형으로 반응한다. 이용률(생산 시간 ÷ (생산 + 대기 시간))이 약 85%를 넘으면 사이클 타임이 크게 늘기 시작한다. 도착 간격·가공 시간의 변동도 변동계수(CV) 제곱에 비례해 대기를 키운다(CV 0.75 미만 낮음, 1.33 초과 높음). 배치 장비는 lot이 한꺼번에 나와 하류의 도착 변동을 키운다.
- **점검**
  1. 리틀의 법칙은 분포와 무관하지만 **같은 대상·같은 기간의 장기 평균**이어야 한다. 처리량은 투입량이 아니라 실제 완료량을 쓴다. 세 값 중 둘로 나머지를 계산해 데이터 정합성 검사에 쓴다.
  2. 처리량 병목(이용률 최고 장비)과 사이클 타임을 가장 많이 늘리는 장비군은 다를 수 있다. X-factor를 순수 가공 시간 비중으로 가중해 기여도를 나눈다. 가공 시간이 짧은 장비일수록 이송·인력 영향으로 X-factor가 커지기 쉽다.
  3. 정비 일정이 몰리면 가용 대수가 줄고 변동이 커진다. 정지 시간을 이용률 분모에 넣지 말고, 대수 $m$을 줄인 경우로 따로 계산한다. Kingman·Sakasegawa 식으로 이용률·변동을 바꿨을 때 대기 변화를 추정한다(근사식이므로 순위 비교용).
  4. OEE·가용률은 SEMI E10 상태 매핑과 분모 정의를 확인한다.
  5. DPW는 근사식이다(노치·샷 배치·부분 다이 제외 무시로 수 % 차이 가능, 다이 종횡비도 영향). 실제 맵이 있으면 맵의 유효 다이 수를 쓴다. 좋은 다이 수 = DPW × 수율.
  6. 단위(lot·웨이퍼, 시간·일)를 맞춘다.

### 주제 14. 측정 시스템 분석 (MSA)
- **메커니즘**: 관측 분산 = 실제 부품 분산 + 측정 분산(반복성: 같은 장비·같은 사람 반복 / 재현성: 장비·사람 간 차이). 측정 잡음이 크면 공정 변화와 불량을 못 가리고, 제어기는 잡음을 쫓아 오히려 흔든다. 교정(치우침)과 정밀도(흩어짐)는 별개다.
- **점검**
  1. 기준 분모가 다르다: %GRR(총변동 대비)은 공정 관리용, P/T(공차 대비)는 합·불 판정용이다. 어느 쪽을 쓰는지 밝힌다.
  2. 연구용 부품을 공정 범위 전체에서 고르지 않으면(비슷한 부품만 고르면) 총변동 대비 %GRR이 부풀려진다.
  3. 기준마다 결론이 다르다(Wheeler 방식은 AIAG보다 덜 엄격). 고객·과제가 정한 기준을 따른다.
  4. 반도체 계측은 단일 장비 정밀도 외에 장비군 매칭 정밀도, 총 측정 불확도를 함께 본다. 같은 웨이퍼를 여러 장비가 잰 쌍으로 장비 간 오프셋을 보정한다(1부 주제 9).
  5. 계측 장비 교체·교정 시점의 계단을 공정 변화로 오인하지 않는다.
  6. 측정이 시료를 바꾸면(파괴 시험 등) 같은 시료 반복이 불가하므로 중첩(nested) 설계로 본다.
  7. 가상 계측·예측 모델의 학습 라벨(실측값)에도 측정 잡음이 있어 오차 하한이 생긴다. 측정 반복성보다 작은 오차를 목표로 삼지 않는다.

### 주제 15. 메모리 소자·테스트 기초
- **D램**: 셀 커패시터의 전하가 새서 주기적으로 리프레시한다. 전 뱅크 REF(DDR4 기본)는 한 번에 여러 행을 갱신하고 그동안(tRFC, 8Gb DDR4 예 약 350 ns) 해당 랭크가 응답하지 않는다. 뱅크 단위 리프레시(DDR5 same-bank 등)는 그 뱅크만 멈춘다. 고온일수록 누설이 빨라 리프레시를 늘린다.
- **리페어**: 셀 배열 옆에 예비 행·열을 두고, 테스트로 불량 주소를 찾아 퓨즈로 대체 경로를 만든다. 레이저 퓨즈는 웨이퍼 단계에서만 쓰고, 전기 퓨즈·안티퓨즈는 웨이퍼 테스트와 패키지 뒤 모두에서 쓴다. must-repair는 행·열 대칭이다: 한 행의 불량 비트 수가 남은 예비 열 수보다 많으면 그 행은 예비 행으로, 한 열의 불량이 남은 예비 행 수보다 많으면 그 열은 예비 열로 반드시 대체한다. 최적 배정은 NP-완전이라 휴리스틱을 쓴다. 예비 자원이 바닥난 다이는 수리 불가 빈으로 간다.
- **낸드**: 쓰기·지우기(P/E) 횟수가 늘수록 원시 비트 오류율(RBER)이 빠르게(지수적으로) 오른다. 수명 말기·고온 보관에서는 리텐션(시간이 지나며 전하 손실)이 흔히 주성분이고, 많이 쓴 블록일수록·고온일수록 리텐션이 짧다. 수명 초반이나 읽기 위주 사용에서는 프로그램 간섭·읽기 간섭·셀 간 간섭이 더 클 수 있다. 문턱 전압 분포가 이동·확대되어 겹치면 읽기 기준 전압을 바꿔 다시 읽고(read retry), LDPC는 경판정 실패 시 연판정으로 넘어가 지연이 커진다. ECC를 강화해도 수명 연장은 체감한다.
- **점검**
  1. 리텐션·리프레시 불량은 테스트 온도 조건부터 확인한다.
  2. 수리 전 수율과 수리 후 수율을 구분한다.
  3. 예비 자원 사용량을 결함 밀도·신뢰성 위험 지표로 쓴다(1부 주제 6 스택 분산과 연결).
  4. 빈 번호 정의는 제품·시기마다 바뀔 수 있으니 정의표를 조인한다(1부 2장).
  5. 낸드 오류는 P/E 횟수·보관 시간·온도 세 축으로 나눠 본다. ECC 정정 뒤 오류만 보면 원시 열화를 놓친다.

### 주제 16. 예지 정비와 생존 분석
- **메커니즘**: $\beta<1$(초기 고장)이면 번인·선별·조립 품질이 답이고 정기 교체는 효과가 없다. $\beta\approx1$(무작위)이면 예방 교체가 이득이 없다. $\beta>1$(마모)일 때만 정기 교체·상태 감시가 이득이다. $\beta$의 신뢰구간이 1을 포함하면 마모라고 단정하지 않는다.
- **점검**
  1. 검열 처리: 관찰이 끝날 때까지 고장 나지 않은 개체와 **예방 교체로 빠진 부품은 검열**이다. 버리거나 고장으로 치면 수명이 짧게 추정된다. 우도에서 고장은 밀도 $f(t)$, 검열은 생존 $S(t)$로 넣는다.
  2. 마모형에서는 평균 수명(MTTF)이 첫 고장보다 훨씬 뒤에 있으니, 교체 계획은 $B_{10}$ 같은 하위 분위수로 잡는다.
  3. 시간축은 달력보다 사용량(RF 시간·처리 매수)을 우선 검토한다(1부 주제 2).
  4. 여러 고장 모드가 섞이면 단일 와이블이 맞지 않는다(욕조 곡선 = 혼합). 고장 원인별로 나눈다.
  5. 미래 정보 누수: 고장 뒤에 적힌 메모·정비 기록을 특징에서 빼고, 시간순으로 분할한다.
  6. 알람 평가는 이벤트 단위로 한다: 고장 전 정해진 구간(H) 안에 알람이 계속 켜져 있었으면 적중, 고장이 따르지 않은 알람 구간은 오경보. 알람과 고장 사이 리드 타임이 조치에 필요한 시간보다 짧으면 쓸모가 없다.
  7. 알람 경계는 1장의 비용식으로 정하고 정확도 기준(0.5)으로 자르지 않는다. 확률이 보정되지 않았으면 검증 구간에서 기대 비용이 최소인 경계를 직접 찾는다.
